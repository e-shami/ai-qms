## Session additions 2026-08-24 (Phase 7-v2, branch `role-based-institution-UI`)

**Role-based workflow split.** Admin and staff now have separate shells/pages; institution short codes anchor a two-step login.

- **Institution codes:** `institutions.code` = 3 name-derived letters + zero-padded id (`SHR016` style), generated post-flush in register, returned by `POST /auth/register` (`RegisterResponse`), shown on the success screen + admin settings. Column stays **nullable at schema level on purpose**: derivation needs the row id, so the value is written in the same transaction after INSERT (NOT NULL broke register with NotNullViolation — found via smoke). UNIQUE index is the seatbelt. Backfill logic inlined in the migration (must not track app util refactors).
- **Login:** requires `institution_code`; new public rate-limited `POST /auth/institution/verify` returns `{name,type,is_active}`. Login also rejects when the *institution* is inactive (was a real hole: deactivated tenants could still sign in). Case-insensitive code matching.
- **Presence:** `personnel.work_status` (`off_duty|available|on_break`, declared by staff via `PATCH /staff/status`); "serving" derived from tokens stamped `served_by_personnel_id` on call/start. Roster broadcast over WS as tagged envelope `{event:"presence",data:{entries:[...]}}`; queue frames are now `{event:"queue",data:{snapshot}}`. FE socket routes envelopes, falls back to legacy untagged snapshots.
- **Staff self-service router** (`/staff/*`, gated on linked active Personnel row, not raw role): workspace one-shot payload (counter+queue+today stats w/ `tz_offset_minutes`), status, counter claim (`SELECT…FOR UPDATE` occupancy check → clean 409).
- **Decline:** new terminal token status + reason column; allowed from waiting/called/in_service. Analytics: `declined` counts additive everywhere; `avg_total_min` now SERVED-only (no-shows previously inflated it).
- **Admin overview endpoint** `/overview/admin`: funnel, today totals, counter board, staff roster, hourly issued-vs-completed series — single round-trip for the dashboard page.
- **Personnel:** create-with-account atomically (single form creates person+login); `user_id` removed from PersonnelCreate (it accepted arbitrary cross-tenant user ids); added admin reset-password (bumps refresh version) and set-login enable/disable endpoints.
- **Institution purge:** `POST /institutions/me/purge {confirm_name}` hard-deletes; must use Core-level DELETE — ORM parent-delete tried to NULL counters.institution_id and hit NotNullViolation before DB cascade fired.
- **Latent bugs fixed:** `/display` route never existed ((display) group collided with root page.tsx — Next silently dropped it; sidebar link was a 404) → real path `app/display/page.tsx`; B2/B3/B4 above.
- **Frontend structure:** `(admin)` dashboard/management/tokens/analytics/settings · `(staff)` workspace · shared `/settings` (role-rendered content — separate group pages collided on /settings) · compat redirects for /overview /live-queue /counters /personnel · shared primitives (PageHeader, StatCard, StatusDot, EmptyState, ConfirmDialog w/ type-to-confirm, base-ui Tabs, MobileNav slide-over in unified DashboardShell) · dependency-free SVG hourly chart + funnel tiles · two-step login form w/ verify card + last-code prefill · staff workspace (presence control, counter switcher, now-serving hero w/ live elapsed timer, rich up-next rows w/ eta_min, decline dialog) · management tabs deep-linkable via ?tab=.
